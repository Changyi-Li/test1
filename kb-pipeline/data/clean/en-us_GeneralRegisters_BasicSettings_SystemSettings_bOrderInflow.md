### Order inflow
These system settings are used to determine how an order inflow should be presented and which data it should be based on. The settings apply for the following procedures: Order inflow, Order inflow – Blanket order as well as the desktop component Order inflow – Chart . This ensures that the information regarding order inflow is consistent regardless of where it is shown. Users are still able to make their own choices and select default values in the above procedures.

#### Select for order type – Basic types
With this system setting you can decide which order types should be included in the company’s order inflow. The following basic types can be chosen:
- New sales
- Stock orders
- Agreements

#### Include orders from
This determines what is default in the Include orders from setting in the order inflow procedures as well as in the desktop component. Here you decide whether inflow should be based on:
- Customer order (default)
- Delivery
- Invoice

#### Include preliminary customer orders
This determines how the Include preliminary customer orders should be configured by default. (Blanket orders cannot be marked as preliminary) The following options are available for the setting:
- Yes (default)
- No

#### Include alloy cost
This determines how the Include alloy cost setting should be configured by default. (This only applies to customer orders. Blanket orders cannot have an alloy cost). The following options are available for the setting:
- Yes (default)
- No

#### Show order inflow for deleted customer orders
This determines how the Show order inflow for deleted customer orders setting should be configured by default. The following options are available for the setting:
- Yes (default)
- No

#### Show called order rows
This determines how the Show called order rows setting should be configured by default. When this setting is not marked, customer order rows that are called from blanket order are hidden. In that case a total of Order inflow and Order inflow – Blanket order will result in the total order inflow. The following options are available for the setting:
- Yes (default)
- No

#### New order inflow
This setting determines which date added order rows should be based on in the Detailed by date (acc. to syst. Setting)­ presentation. When you add a new order row, will order inflow be presented as per order date or log date? The following options are available for the setting:
- Order date – When order date is selected, the presentation shows new order rows with Date = Order date (default).
- Log date – When log date is selected, the presentation shows new order rows with Date = Log date.

#### New order inflow at delivery
This setting determines which date new order inflow at delivery should be based on in the Detailed by date (acc. to syst. Setting)­ presentation. When you add a new order row at delivery, will order inflow be presented as per delivery date, order date or log date? The following options are available for the setting:
- Delivery date – When delivery date is selected, the presentation shows new order rows with Date = Delivery date (default).
- Order date – When order date is selected, the presentation shows new order rows with Date = Order date.
- Log date – When log date is selected, the presentation shows new order rows with Date = Log date.

#### Changed order inflow
This setting determines which date changed order inflow should be based on in the Detailed by date (acc. to syst. Setting)­ presentation. When you add a new order row, will order inflow be presented as per order date or log date?
The value of the order inflow will change when any of the following are edited or if the order row is deleted:
- Quantity
- Price each
- Discount
- Setup price
The following options are available for the setting:
- Order date – When order date is selected, the presentation shows new order rows with Date = Order date (default).
- Log date – When log date is selected, the presentation shows new order rows with Date = Log date.
