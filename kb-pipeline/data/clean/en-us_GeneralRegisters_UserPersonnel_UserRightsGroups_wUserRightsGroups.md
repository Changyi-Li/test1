## User rights groups
In this procedure you can register own user rights groups if needed. These groups are used a complement to roles set on users, as re-usable collections of user rights. A user can have several user rights groups of which one should be set as default.
When you start up the system for the first time, there are no user rights groups. Normally, user rights groups are not necessary since there are built-in user rights in the pre-defined roles. However, sometimes there are no roles that suit or you might need to adjust several user's user rights. It is then possible to apply user rights groups for users.
Another area of use for user rights group is to automatically load default values (saved in selections to lists), based on the user's default user rights group when the user opens such a procedure.
> A difference compared to roles is that user rights groups can either allow or deny different activities. Roles can only allow activities. Deny is ranked higher than Allow. If for example a user has a role that allows a specific activity but at the same time belongs to a user rights group that deny the same activity in the Users procedure, the user will not be allowed to perform the activity. This will also be displayed in the box Resulting user rights in that procedure.
