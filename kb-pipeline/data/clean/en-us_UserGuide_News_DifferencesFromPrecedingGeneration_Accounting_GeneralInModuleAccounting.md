### General in the Accounting module

#### Dimensions
In G4 there was a limitation of three dimensions (cost center, cost unit, and project). In G5 there is a dynamic handling of up to eight dimensions in addition to Account. Furthermore, it is possible to name the dimensions as you please. This is done in the DimensionsDimensions are used by large companies in their accounting in order to divide up activities and make it easier to track internal results. An account is a dimension, although large companies usually use the dimensions cost center (CC), cost unit (CU) and project. In addition to these you can create other dimensions in Monitor ERP based on your own operational follow-up. procedure. You can link dimensions to different registers in the system, so this is automatic in the posting. For example, to create dimensions relating to Department, Customer, Part and Employee, etc.
As standard, many lists showing coding/posting items are configured to show the three standard dimensions for cost center, cost unit, and project. When increasing the number of dimensions it is required that you add columns for the new dimensions via configuration of lists (on the places where they are to be shown). One exception for this is the journal printouts.

#### Specification in posting rows
The Specification field on posting rows has been increased to 100 characters. In G4 the limit was 50 characters.

#### Date instead of period
In G5 you work with accounting periods in the same way as in G4. However, balances etc. are saved in detail by date. This means that you in most lists in the accounting select by date instead of by period. This makes it possible to for example print result income statement down to day level instead of for entire periods.

#### Currency
There is now an improved support for currencies in the accounting. In G4 the currency amount was coded via the Quantity field. In the Specification field you could see the currency code. In G5 there is a separate currency field in accounts payable/accounts receivable, and in general ledger transactions where the external currency is coded/posted and which also shows the currency code for the transaction. Exchange rate is also saved on the transactions in the general ledger. Currency coding/posting in general ledger is only done for accounts which are marked as currency accounts in the chart of accounts, for example bank account in external currency.

#### VAT
You can let the account be determining of the VAT report, the same way as in G4. For example, you need to register separate sales accounts for Sweden, EU, and Export, in order to create a correct VAT report. A new feature in G5 is that you can disconnect the chart of accounts from the VAT report. This is done via a system setting. In that case the VAT report will instead read the VAT code for each general ledger transaction in order to determine how the sales/purchase should be recorded. When you use the system in this way, the VAT code field is used in all posting windows in the system, both in accounts receivable/accounts payable and in the accounting. VAT code for transactions created in the Sales module and the Purchase module is configured based on the VAT group on customer and supplier. The link between VAT code and VAT row is defined in the procedure VAT settings. However, the actual VAT accounts work in the same way as before and are determined by VAT row in the chart of accounts.
