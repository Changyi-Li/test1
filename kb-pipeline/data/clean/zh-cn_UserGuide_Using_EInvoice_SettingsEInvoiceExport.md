### 电子发票导出设置
你必须先已配置以下设置，之前发送电子发票 Monitor ERP。
> 您的防火墙必须打开端口443 或 80 以传输传出流量，仓储费用您的系统才能与 Crediflow 进行通信。
电子发票导出设置
> VAT 登记号你在​ 公司信息 配置低于设置之前的程序。如果你需要有关如何输入电子发票信息的帮助，联系人我们的支持中心。
在你开始使用系统中的电子发票服务之前，必须已配置以下设置：
1. 打开 导出 标签页卡中的 导出 / 导入设置 程序。
2. 选择 电子发票 在导出类型下。
3. 检查 电子发票信用流。
4.       
点击 创建科目 按钮。无论你是否已拥有 Creditflow 的“PartyID”，都应执行此操作，因为该程序运行检查PartyID 是否存在。如果仓储费用, 你 的 PartyID 将会 被 载入 并且否已创建新科目.
如果你不PartyID，将会已创建一个新科目。一次已创建科目，公司 ID将自动填写。当你激活该功能时，您的公司也将在电子发票网络中已激活以接收发票。
确保公司信息正确，并输入联系人及其联系信息。
还输入“邀请信息”。当你向客户发送邀请询问客户是否希望收到你的接收电子发票时使用此消息。
如果你已已登记GLN 号(全球库位编号)，请联系人MONITOR支持中心以获取帮助，以便在您的科目上激活该号码。
5. 电子发票地址 (EIA) 已自动输入。此信息是满足系统中 Peppol格式校验所必需的。电子发票地址可以例如企业 ID 号或VAT 登记号。
6. 电子发票地址 ID (EAID) 已自动输入。此信息是满足系统中 Peppol格式校验所必需的。在芬兰，EAID 通常为“LY-tunnus”。
7.   
将嵌入的 PDF 附在 XML 中 决定是否应将嵌入式 PDF 附加到带有电子发票的 XML文件中。该设置默认处于激活由，如果你希望附加 PDF文件，则你人工的激活它。
8.   
激活发送发票的测试模式。如果你激活测试模式，你可以发送发票以测试电子发票中的数据。测试将针对 Crediflow 的实时端点进行，但使用测试数据。你发送的发票在导入时将作为实时发票处理。不过，数据将保留在 Crediflow 中，与非继续在流程中流动。这意味着你可以测试状态调用等。
9.   
那个设置 电子发票文件手工验证路径 用于测试/验证电子发票。如果你输入路径， 保存到文件 显示在 电子发票 列中的 复审 / 批准发票 和 打印发票 程序，你可以选择将电子发票保存到你在此处输入的路径中的文件中。时间，电子发票也会已发送给操作员/客户。其目的例如是将电子发票发送到支持中心进行故障排除（通过重新打印），或者在正式上线之前将其发送给客户进行验证。如果你在路径中输入一些内容，这将覆盖设置 激活发送发票的测试模式。
10. 使用 创建科目 如果你不拥有 Crediflow科目，请按按钮登记一个Crediflow 帐户。确保公司信息正确，并输入联系人及其联系信息。还输入“邀请信息”。当你向客户发送邀请询问客户是否希望收到你的接收电子发票时使用此消息。如果你已已登记GLN 号(全球库位编号)，请联系人MONITOR支持中心以获取帮助，以便在您的科目上激活该号码。
11.   
检查 我已阅读并接受此服务的条款 / 条件 盒子。
12. 科目​​ OK。这是通过与 Crediflow 的 API连接进行的。如果一切正常，你将自动收到您的公司 ID。现在，科目登记已已完成。如果科目登记失败，你可以阅读更多低于了解更多信息。
13. 保存。

#### 注销账户
如果你已经拥有Crediflow 帐户，你可以注销该科目，案件你否发送电子发票。

#### 科目登记已失败
最常见的科目登记已失败是由于公司信息/组织信息被不同的电子发票操作员“已锁定”。在这种案件下，你必须第一个联系人您的旧的操作员并要求他们释放您的组织信息。之后你就可以登记一个科目。
