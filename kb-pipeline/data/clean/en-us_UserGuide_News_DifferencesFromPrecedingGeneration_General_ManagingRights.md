### Managing user rights
In G5 it is possible to specify user rights for the user based on what he/she should be able to do in the system. The user rights lead to which menu items (procedures) are available when logging in. This is based on what the user is allowed to do. One example is to grant complete user rights to Part, which gives the user access to the procedures Part register, Stock transaction log, BOM and routing, etc. If a certain user should not be allowed to access the BOM and routing procedure (for example because he/she is a purchaser), then it is possible to exclude that procedure even though the user has complete user rights to the Parts section.
Users get user rights from the user-specific user rights and the role they belong to. To be able to add and delete user rights compared to the role you can create user rights groups which the user can belong to. A user rights group can both be configured to allow and deny user rights/permissions.
This means the resulting user rights depend on the role, which user rights group the user belongs to, and how the user-specific user rights are configured.
In G4 menu items and user rights were the same thing.
